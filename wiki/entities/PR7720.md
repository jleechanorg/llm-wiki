## Purpose

Fixes the iOS WebKit IndexedDB persistence deadlock that rendered the mobile game page blank/hung and required a full cold browser restart to clear. The bug stemmed from Firebase Auth compat SDK 9.6.1 resolving `Persistence.LOCAL` to `indexedDBLocalPersistence`, which deadlocks on iOS WebKit after OS process suspension (firebase-js-sdk #8019).

## Fix (one line, idempotent)

```js
Object.defineProperty(window, 'indexedDB', { configurable: false, value: undefined });
```

Placed before the first `firebase.auth()` call. Forces Firebase's `_isAvailable()` probe to fail for the IndexedDB persistence backend, so `LOCAL` falls back to `browserLocalPersistence` (localStorage). The hang is structurally never entered.

## Verification

Three real-WebKit surfaces:
- Playwright WebKit RED/GREEN matrix (6 checks)
- Real shipped auth.js in WebKit with IndexedDB hung stub
- Real iOS 18.6 Simulator (MobileSafari) — captioned RED→GREEN GIF

Strongest proof: deployed build renders sign-in (not blank) on real iOS Simulator; verified by raw HTTP capture of served auth.js containing the neutralization block.

## Honest limitations

- Organic reproduction (no stub) was unreachable — the hang is a device-level OS-process-suspension property off-real-device.
- One-shot re-login required for users with existing IndexedDB-stored sessions after deploy.
