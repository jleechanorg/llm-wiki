# rtk diff-truncation mechanism (2026-09-11)

## Summary

`rtk` (Rust Token Killer, https://www.rtk-ai.app/) is a real, installed Homebrew
formula on this Mac. It compacts `git diff` / `gh pr diff` output not via a
shell alias/function or a git config setting, but via a **Claude Code
`PreToolUse` hook** that rewrites the literal `Bash` tool-call command before
it ever reaches the shell. This is harness-level interception, not a
shell-level shim.

## 3. Actual mechanism: a Claude Code `PreToolUse` hook

`~/.claude/settings.json` (grep hit at line 254):
```
239:            "command": "bash ~/.claude/hooks/PreToolUse.sh",
240:            "timeout": 5000
...
244:      {
245:        "matcher": "Bash",
246:        "hooks": [
247:          {
248:            "type": "command",
249:            "command": "bash ~/.claude/hooks/pre-commit-detached-guard.sh",
250:            "timeout": 5000
251:          },
252:          {
253:            "type": "command",
254:            "command": "bash ~/.claude/hooks/rtk-hook-guard.sh",
255:            "timeout": 5000
256:          },
257:          {
258:            "type": "command",
259:            "command": "bash ~/.claude/hooks/enforce-claudeaf-agentf.sh"
```

`~/.claude/hooks/rtk-hook-guard.sh` (full contents):
```bash
#!/usr/bin/env bash
# rtk-hook-guard - skips rtk when CLAUDEM_MODE is set
# Used as PreToolUse Bash hook; claudem() sets CLAUDEM_MODE=1

if [[ "${CLAUDEM_MODE:-0}" == "1" || "${CLAUDEW_MODE:-0}" == "1" ]]; then
  # No output means allow the original tool input unchanged.
  exit 0
fi

exec rtk hook claude "$@"
```

So every `Bash` tool call Claude Code is about to execute is first piped
(as PreToolUse-hook JSON on stdin) through `rtk hook claude`, which can
**rewrite the command before it runs**. Direct proof, run in this session:

```
$ echo '{"tool_name":"Bash","tool_input":{"command":"git diff HEAD~1 HEAD"}}' | rtk hook claude
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecisionReason":"RTK auto-rewrite","updatedInput":{"command":"rtk git diff HEAD~1 HEAD"},"permissionDecision":"allow"}}

$ echo '{"tool_name":"Bash","tool_input":{"command":"gh pr diff 9871 --patch"}}' | rtk hook claude
{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecisionReason":"RTK auto-rewrite","updatedInput":{"command":"rtk gh pr diff 9871 --patch"},"permissionDecision":"allow"}}

$ echo '{"tool_name":"Bash","tool_input":{"command":"git show HEAD"}}' | rtk hook claude
{"hookSpecificOutput":{...,"updatedInput":{"command":"rtk git show HEAD"},...}}

$ echo '{"tool_name":"Bash","tool_input":{"command":"git log -p -1"}}' | rtk hook claude
{"hookSpecificOutput":{...,"updatedInput":{"command":"rtk git log -p -1"},...}}
```

`git show HEAD` and `git log -p -1` (task item 5) are rewritten identically —
**any** command whose first token literally matches `git`/`gh`/etc. gets
silently substituted with an `rtk <subcommand>` invocation, which then applies
its own compaction/truncation logic to the real command's output before
Claude ever sees it.

Critically, an **absolute-path invocation bypasses the rewrite entirely**:
```
$ echo '{"tool_name":"Bash","tool_input":{"command":"/usr/bin/git diff HEAD~4 HEAD"}}' | rtk hook claude
# (no stdout at all — no JSON returned, meaning "allow unchanged", i.e. pass-through)
```
This is exactly why the original observation (`/usr/bin/git diff` returning
the full 3127-line unified diff vs. bare `git diff` returning a 552-line
compacted one) occurred: `rtk hook claude` pattern-matches the leading
command token (`git`, `gh`, ...) literally, not the resolved binary, so
`/usr/bin/git ...` never matches and is passed through untouched.

## 4. `--no-compact` flag

Not listed in any `--help` text (`rtk git diff --help` only shows
`-v/--verbose`, `--ultra-compact`, `--skip-env`, `-h/--help`), and not
mentioned in `/opt/homebrew/Cellar/rtk/0.38.0/README.md` or `CHANGELOG.md`
(grep for "no-compact" in both returned zero hits). It is, however, a real,
functional, **undocumented** flag — confirmed by direct execution in this
repo:

```
$ rtk git diff --no-compact HEAD~4 HEAD | head -5
diff --git a/pyproject.toml b/pyproject.toml
index 31c4cdcf309..8bc7c445b30 100644
--- a/pyproject.toml
+++ b/pyproject.toml
@@ -230,10 +230,13 @@ testpaths = [
```
This is the full, standard unified-diff format (with headers), matching what
plain `/usr/bin/git diff` produces — i.e. `--no-compact` genuinely disables
rtk's compaction and forwards the real subprocess output. This is presumably
the flag rtk's own footer message ("[full diff: rtk git diff --no-compact]")
is telling the caller to use to retrieve the untruncated diff — confirmed
working here, just not present in `--help` output for this installed version
(0.38.0; may be documented in the newer 0.48.0 release notes not present
locally).

## 5. Other commands affected

Confirmed via the same `rtk hook check`/`rtk hook claude` dry-run mechanism:
- `git show HEAD` → rewritten to `rtk git show HEAD`
- `git log -p -1` → rewritten to `rtk git log -p -1`
- `gh pr diff <N> --patch` → rewritten to `rtk gh pr diff <N> --patch`

So this is not diff-specific — any Bash tool call beginning with a bare
`git`/`gh` token (among the ~30 other wrapped tools: `pytest`, `docker`,
`kubectl`, `cargo`, `pip`, `go`, `prettier`, `playwright`, etc.) goes through
the same rewrite-then-compact pipeline.

## 6. Fix path: user-owned config, not a binary patch

`rtk init --help` documents first-class, user-controllable management of this
exact hook:
```
-g, --global              Add to global assistant config directory instead of local project file
    --agent <AGENT>       Target agent to install hooks for (default: claude)
    --show                Show current configuration
    --auto-patch          Auto-patch settings.json without prompting
    --no-patch            Skip settings.json patching (print manual instructions)
    --uninstall           Remove RTK artifacts for the selected assistant mode
```
This confirms the hook is entirely a **user-owned configuration artifact**
(`~/.claude/settings.json` + `~/.claude/hooks/rtk-hook-guard.sh`), installed
by `rtk init` and removable by `rtk init --uninstall` or by manually deleting
the `rtk-hook-guard.sh` hook entry from `settings.json`. It is not baked into
the `rtk` binary itself requiring an upstream patch/report, and it is not a
Claude Code core/harness feature — it is a hook Claude Code's `PreToolUse`
mechanism was designed to support, which this specific rtk-authored script
happens to use.

The guard script also already supports a **soft, session-scoped bypass**: if
`CLAUDEM_MODE=1` or `CLAUDEW_MODE=1` is set in the environment the hook
process inherits, it exits 0 with no output (pass-through, no rewrite). Per
`~/.bashrc:1057`, `claudem()` is a shell function that sets `CLAUDEM_MODE=1`
for its invocation — i.e. there's already a documented, user-owned way to run
a whole session/command with rtk disabled, separate from per-command
`--no-compact`.

## Answers to the orchestrator's 6 questions

1. **Binary**: `/opt/homebrew/bin/rtk` → symlink → `/opt/homebrew/Cellar/rtk/0.38.0/bin/rtk`, a real Homebrew-core Rust binary, "Rust Token Killer", not the same-named tool as anything else.
2. **Interception mechanism**: Claude Code `PreToolUse` hook (matcher `"Bash"`) in `~/.claude/settings.json` invoking `~/.claude/hooks/rtk-hook-guard.sh`, which execs `rtk hook claude "$@"` on the tool-call JSON via stdin and returns a JSON `updatedInput.command` rewrite (`git diff ...` → `rtk git diff ...`). Not a shell alias/function, not `~/.gitconfig`/`.git/config`, not `GH_PAGER`/`PAGER`/`GIT_PAGER`.
3. **Harness-level, confirmed**: yes — it is baked into the Claude Code harness's hook config (`~/.claude/settings.json`), executed by the harness before the Bash tool runs the command, not a real shell-level shim the user typed into `.bashrc`/`.zshrc`.
4. **`--no-compact` flag**: undocumented in `--help`/README/CHANGELOG for the installed 0.38.0, but functional — verified directly, produces the full standard unified diff.
5. **Other commands affected**: yes, confirmed for `git show`, `git log -p`, and `gh pr diff`; by design (per `rtk --help`) it also wraps `pytest`, `docker`, `cargo`, `pip`, `go`, `playwright`, and ~20 others whenever invoked via a bare (non-absolute-path) command name.
6. **Provenance**: real Homebrew-core formula, installed 0.38.0, "Installed (on request)", stable is 0.48.0 (10 versions ahead) — not a custom/internal binary.
