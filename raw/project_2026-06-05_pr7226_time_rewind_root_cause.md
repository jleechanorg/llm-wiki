For campaign `i9xdU7P2bNoMpGqfLBHe`, Cloud Run logs and Firestore docs prove the
time-travel failure is not only session-header enrichment drift. The failing
turn was served by `mvp-site-app-dev`, routed to `GodModeAgent`, and generated by
`gemini-3-flash-preview`. Gemini emitted `state_updates.world_data.world_time`
rewinding from `150 AF, February 14, 06:45` to
`150 AF, February 11, 11:44`; the server logged `Time regression detected` but
persisted because monotonicity validation used `strict=False`.

**Why:** Future PR 7226 or temporal-consistency work must not overclaim header
repair as fixing full narrative/state rewinds.

**How to apply:** Fix prompt/schema ambiguity first so God Mode lore corrections
do not authorize time travel, then add a narrow pre-persistence backend invariant
that rejects, strips, or retries regressive `world_time` unless explicit rewind
authorization is present. Tracking: `rev-lzpla` and
https://github.com/jleechanorg/worldarchitect.ai/issues/7307.
