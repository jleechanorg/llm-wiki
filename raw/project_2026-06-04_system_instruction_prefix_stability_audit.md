User asked (2026-06-04): "look at real http requests to the llm both local and gcp and ensure that some parts of system instructions are truly 100% static like no IDs/timestamps injected." This is the prefix-stability prerequisite for cache-redesign design A (shared per-agent system-instruction cache vs the current per-campaign keying in gemini_cache_manager.py:72/196).

**Method (REAL wire-level capture, no mock):** Diffed actual Gemini HTTP request bodies already on disk at `/tmp/worldarchitect.ai/feat_levelup-prompt-consolidation/test_level_up_organic/iteration_001/gemini_http_request_responses.jsonl` (17 http_request records, real `systemInstruction.parts[].text`). Capture mechanism = `GEMINI_HTTP_REQUEST_RESPONSE_CAPTURE_PATH` monkey-patch of httpx.Client.send in gemini_provider.py:483 (`_gemini_http_capture_context`); LLM-layer twin = `LLM_REQUEST_RESPONSE_CAPTURE_PATH` (`system_instruction_text`, llm_service.py:5660/5619, gated by CAPTURE_RAW_LLM=true). testing_mcp base class auto-sets both paths. Full system_instruction is NOT in GCP prod logs (FULL_SYSTEM_INSTRUCTION is logging.debug @ llm_service.py:5558, Cloud Run min severity INFO); GCP proxy = `GEMINI_REQUEST` INFO size line (gemini_provider.py:938). To capture GCP wire-level, run testing_mcp with `--server <preview-url>` — HTTP capture still writes locally.

**Empirical findings (the answer):**
- **Truly-static cross-agent prefix = master_directive.md only: chars 0..18,639 (~4.6K tok), byte-identical across ALL 17 requests** regardless of agent. Divergence begins exactly at the master_directive boundary.
- **NO dynamic IDs injected into system_instruction:** zero campaign_id, zero UUIDs. The 42 "20-char id" regex hits were false positives (CamelCase schema words: ActionResolutionRoll, PlanningChoiceLegacy, additionalProperties).
- **NO injected real-world dates/timestamps:** every date/time token is STATIC — doc-version headers (`Last Updated: 2026-04-13` in master_directive.md; `2026-02-11` in level_up_instruction.md) and JSON schema EXAMPLE values (`"updated_at":"2025-12-24T18:00:00Z"`, `Timestamp: 1492 DR`, `14:30:00`). In-game world-time lives in the TEMPORAL CONSISTENCY ENFORCEMENT continuation block (agent_prompts.py:2392) and only changes when in-game time advances — not wall-clock, not per-request.
- **Within a stable window the WHOLE system_instruction is byte-identical:** records 22–32 = 6 consecutive same-agent requests identical end-to-end (363,296 chars); records 0,2,4 = 3 identical (312,797). So caching DOES hit within a campaign-state epoch.
- **Length grows 312,797 → 363,296 over the session.** The growth is dynamic CONTENT accretion in system_instruction (Character Identity block, god_mode directives, companions, arc reminders, campaign setting, LLM-requested sections), NOT story_history (that's in `contents`).

**ROOT CAUSE (why the static prefix is only 4.6K tok, not ~60K):** `agent_prompts.py:2650` `parts.insert(1, identity_block)` inserts the variable-length **dynamic** Character Identity block at index 1 — between master_directive (idx 0) and the ~37K-tok static `game_state_instruction.md`. God_mode directives insert at idx 2 (`:2658-2659`); campaign setting appended (`:2667`). The big static .md blocks (game_state, planning_protocol, narrative, mechanics) are static TEXT but sit at a VARIABLE byte offset, so they can't form a cache prefix. The blocker is **insertion ordering, not timestamps/IDs** — there are none.

**Actionable (rev-n6nbs, task #20):** Reorder finalize_instructions so all static .md content is a contiguous prefix (master+game_state+planning+narrative+mechanics ≈ 60K tok) and ALL dynamic blocks (identity, directives, setting, temporal, deferred, companions, requested-sections) move to the TAIL. Then re-key the explicit cache on `(agent_type, dice_strategy)` instead of `campaign_id` → storage collapses from O(active_campaigns × 60K × TTL) to O(~6 agents × 60K × TTL), shareable across ALL users/campaigns. This is a ZFC/RCF-clean prompt-assembly fix (no backend protection). Validate net-of-storage in BQ before claiming savings — the read-discount-only justification at llm_service.py:2542-2543 ("78% cost reduction") ignores storage rent, the same blind spot that made cache-storage 55% of spend pre-#7215.

**CORRECTION + FEASIBILITY (2026-06-04, governing):** Two earlier framings were wrong/incomplete. (1) Cache is NOT re-minted every turn — `should_rebuild()` uses `REBUILD_THRESHOLD=10` (gemini_cache_manager.py:93-141), rebuild ~every 10 entries or on model/tool/TTL/state change. (2) The "shared system cache + per-campaign story-DELTA cache (two caches in one call)" design is **NOT constructible**: `GenerateContentConfig.cached_content` is `Optional[str]` (verified `types.py:5983`) — exactly ONE explicit cache per request. The viable design is a SINGLE shared explicit cache holding ONLY globally-identical `system_instruction`+`tools`, OR (better) implicit-only.

Verified SDK/API facts: system/tools-only cache (`contents=None`) IS constructible (`CreateCachedContentConfig` all-optional, only `model` required; `caches.py:128-182`) BUT referencing `cached_content` while ALSO setting `system_instruction`/`tools` on the request → server **400** (system must move fully into the cache). Min cache 2,048 tok (2.5)/4,096 (3.x) — floor clears 10-30×. Explicit read discount **90%** (2.5+), storage **$1/1M-tok/hr**. **Implicit caching is ON by default (2.5+): 75% discount, ZERO storage, ~1,024-tok min prefix** — so a contiguous static prefix is discounted 75% for FREE with no storage rent and no leakage. That makes "implicit-only + reorder" the likely winner; the shared explicit cache is an optional escalation to 90% with small SHARED storage.

**Hard safety boundary:** a shared cache may contain ONLY globally-identical system+tools — NEVER user_id, campaign prompts, world/character data, story, or memories. Because today `system_instruction` carries dynamic per-campaign blocks (identity/directives/setting at :2650/:2658/:2667), the reorder (move them OUT to `contents`) is a SAFETY PREREQUISITE, not just an optimization. **Now framed as a measured SPIKE (rev-n6nbs, task #20)** with 5 acceptance criteria: (1) prove system/tools-only cache accepted+discounts floor; (2) one cache reused ≥2 campaigns, zero leakage; (3) measure 3 options (baseline / implicit-only / shared explicit) net-of-storage in BQ; (4) determine key dims = model+prompt-hash+tool-sig(+schema); (5) only then decide to implement.

Builds on [[cache-off savings PROVEN via BQ billing]] (#7215 zeroed cache-STORAGE SKU) and the cache-redesign discussion. Complements [[rev-bdeez]] (#7243, floor slimming) and [[rev-6m0pt]] (#7244, story cap). Reorder is orthogonal to slimming — it makes whatever floor remains cacheable as a shared/implicit prefix.
